## 브라우저 검사

Windows Chrome headless, viewport 1280×900 및 390×844, Playwright Core 1.65.1. 브라우저 자동화 도구는 QA 전용이고 실행 서버에 노출하지 않는다. 합성 카메라 장치와 합성 landmark 주입으로 검사했으며, 실제 사람이 수행한 검사가 아니다.

- 실제 로컬 페이지/manifest/영상/좌표와 기존 pinned MediaPipe 모델 로딩 성공.
- 실제 영상 크기 1440×1440, 합성 카메라 및 추론 canvas 640×480 확인. 중앙 contain 합성으로 비율을 보존함.
- 실제 가림 영상과 카메라 테스트 패턴이 동시에 보이는 `preview.png`를 육안 확인. 가림 원 유지, 초록 선택 테두리, 투명도·진행·재시작 UI 표시 확인. 이것은 실제 사람 손 가독성 확인을 대체하지 않음.
- 원래 관문→실제 영상 재생→7개 구간 기록→점수→결과 화면→실제 JSON 다운로드 통과. 점수는 합성 입력 결과로만 취급함.
- 순서가 바뀐 두 손 패킷에서 선택된 손만 좌우손 판정·관문 hold·수행 프레임에 유입됨을 직접 확인.
- 누락은 null 기록 및 hold reset. 유예 만료 시 segments/curSegFrames/hold/selectedHand/handednessBuffer가 모두 비워짐을 확인.
- 처음부터 다시 시작 버튼이 새 카메라 초기화 및 detecting_hand 상태로 돌아옴을 확인.
- 페이지 JavaScript 예외 0. 영상 교체·페이지 재시작 시 `net::ERR_ABORTED` 요청은 있었으나 영상 로딩 오류/404는 없었음.
- 카메라 권한이 없는 별도 브라우저 컨텍스트에서는 `NotAllowedError`와 권한·다른 앱 확인 안내가 표시됨.
- 이 환경의 Chrome headless GPU 경로에서 단색 화면을 관찰했고 QA 실행의 `--disable-gpu`로 정상 표시를 확인함. 일반 사용자 브라우저에서의 재현 여부는 확인 대기이며 실행 서버에는 브라우저 플래그를 강제하지 않음.

## 실제 카메라 확인 대기

- 혼자 손을 넣어 목표 따라 하기와 전체 완료/저장.
- 실제 크기가 다른 여러 손·순서 변경·크기 동률·교차 중 선택 유지/무효화.
- 실제 소실·재진입과 새 시도 시작.
- 장치별 셀피 미러, 가림 배경 대비, 손을 움직일 때 1500ms 유예/350ms 안정화의 적절성.

화면상 크기는 실거리·신원 확인이 아니다. 서로 비슷한 손의 동일 위치 대체는 단안 연속성 휴리스틱만으로 완전히 구분할 수 없다. 카메라/모델 하드웨어별 속도와 실제 사용자 편의성 효과는 아직 검증하지 않았다.
