# prod 기반 UI 전체 조합 비교

기존 `hand_captcha_prod.html`에서 만든 연구용 비교본이다. root prod 파일은 수정하지 않는다. 초기 무가림 노출과 가림 페이드도 추가했고, 모든 UI 수정의 켜기/끄기 조합을 선택한다. 이 폴더에는 실제 영상·좌표·사람 응답을 포함하지 않는다.

## 순서와 여섯 비교 항목

연구 전체 순서는 codex의 `docs/research_goal_followups_2026-11-10.md` 「실행 순서와 기존 백로그 연결」을 따른다. UI에서는 기존 명세의 A1/A2 손 선택·유지 → B1 중첩 → B2 안내 → E1 개별/조합 검사 → E2 실제 관찰 후 결정 순서를 따른다. 기존 세 안내안을 별개 대안으로만 비교하던 범위를 사용자 요청에 따라 결합 상태까지 확장했다.

| 비트 | 켠 조건 | 끈 조건 |
|---|---|---|
| 1 | 큰 유효 손 안정 선택·유지 연결 | 기존 prod의 단일 손 처리 |
| 2 | 카메라에 목표 영상 45%로 중첩 | 기존 분리 화면 |
| 4 | A 손바닥 안내 문구 | 추가 문구 없음 |
| 8 | B 손바닥/손등 비교 그림 | 추가 그림 없음 |
| 16 | C 기존 회색 손 가이드에 손금 표시 | 기존 회색 가이드 |
| 32 | 첫 목표 정지 프레임 무가림 500ms → 500ms 동안 가림본으로 페이드 | 같은 1초 동안 계속 가림본 |

총 64개이며 `design.json`은 관측 결과가 아닌 조건표다. `ui-00`은 **이 연구용 공통 절차 안의 기준 구성**이지 역사적 prod 세션의 완전 재현이 아니다. 먼저 기준·단일 수정 6개를 검사한 뒤 나머지 결합을 확인한다. 동일 조건의 효과를 보려면 다른 비트를 고정한 대응 조건을 비교한다. 손 선택은 입력 처리도 바꾸는 요인이므로 다른 안내 효과와 분리해 해석한다.

## 초기 노출을 정확히 정의한 방법

‘처음 약 0.5초 보여 주기’를 **첫 목표의 같은 정지 프레임**을 500ms 보여 주는 것으로 구현했다. 그 뒤 같은 시간·구도의 가림 프레임이 500ms에 걸쳐 나타난다. 처음 0.5초의 동작을 재생하는 조건은 별도이며 구현하지 않았다. 두 조건 모두 가림/원본을 미리 읽은 뒤 같은 1초의 준비 시간을 갖고 이 동안 자세 관문·점수 기록을 시작하지 않는다. 선택 손 추적은 계속해 1초의 준비 때문에 손 소실로 오판하지 않는다. 이후 기존 점수 산식·관문으로 진행한다.

중첩 표시는 원래 카메라 이미지를 복사한 표시용 캔버스에만 그린다. 검출기로 보내는 입력은 기존 `cameraVideo` 그대로다. 미러·종횡비를 보존하고 반복 알파 누적으로 화면이 짙어지는 일을 막는다. 중첩에서 C 안내와 목표 표시가 겹치지 않도록 배치한다.

## 열기

저장소 루트에서 다음을 실행한다.

```text
python -m experiments.preview_server --port 8767
```

`http://127.0.0.1:8767/experiments/prod_ui_factorial/`에서 여섯 스위치와 전체 조건표를 확인한다. 미리보기는 예시 손이며 모델·카메라를 실행하지 않는다. 미리보기 캡처를 실제 촬영이나 사람 결과로 해석하지 않는다.

‘비공개 자료로 열기’는 같은 촬영의 가림본 영상, 무가림 원본 영상, 대응 `video_info`/`frames[].landmarks_px` JSON을 로컬 파일로 받는다. 원동작 계열 코드를 입력하고 대응·연구 사용 범위를 확인한 뒤 카메라를 시작한다. 두 영상의 크기·기간·좌표 시간축을 확인하지만, 이 검사만으로 실제 대응이나 권리를 인증하지 않는다. 프레임 단위 대응과 가림은 기존 pipeline 검수를 먼저 통과해야 한다. 브라우저에서 디코딩 가능한 영상을 사용한다. FFV1 MKV는 지원되지 않을 수 있다.

현재 새 원본이 없는 개발 진단을 위해 한 원동작의 keyframe 흐름을 사용한다. 원래 prod의 두 clip 무작위 선택과는 다르며, 모든 64조건에 같은 절차를 적용한다. 연구 참가자·표본·채택 기준을 임의로 채우지 않는다.

파일은 브라우저 메모리에서만 읽으며 자동 업로드·좌표 다운로드는 비활성이다. 모델 실행을 선택할 때 기존 MediaPipe 라이브러리를 내려받지만 선택 영상이나 카메라 프레임을 업로드하는 코드는 추가하지 않았다. 페이지 종료 시 object URL과 카메라를 해제하며 원래 디스크 파일은 삭제하지 않는다. 결과 화면을 자동 새로고침하지 않고 명시적 ‘시도 기록 저장’으로 조건·시간·이벤트·집계 점수를 로컬에 저장한다. 원본을 브라우저에 제공하는 연구 도구이므로 비밀 정답을 보호하는 운영 송출 경로로 사용하지 않는다.

## 구현 검사

```text
python experiments/prod_ui_factorial/build.py
node --test experiments/prod_ui_factorial/conditions.test.cjs experiments/hand_selection/selection.test.cjs experiments/prod_selected_hand/bridge.test.cjs experiments/prod_selected_hand/async.test.cjs
python -m experiments.prod_ui_factorial.browser_check --output PRIVATE_ARTIFACTS/NEW_RUN --ffmpeg PATH_TO_FFMPEG
```

마지막 명령은 테스트 환경에 `websockets`와 Chrome이 필요하다. 64개 조합×PC/모바일 화면, ID 충돌·가로 넘침·안내 연결·노출 시간·페이드 픽셀을 확인한다. FFmpeg를 제공하면 자체 생성 영상과 가짜 카메라/검출기로 모든 64개 시작·준비 관문·중단 경로도 검사한다. 실제 사람이나 MediaPipe 추론 결과가 아니다. 스크린샷과 브라우저 profile은 새 Git 밖 `private_artifacts` 아래에만 저장한다.

## 실제 효과 비교에 필요한 입력

2026-11-13 실행 결과: 관련 Node 24개, 64조합×2크기 화면/픽셀 128건, 별도의 64조합 합성 카메라 시작·준비·중단 경로가 통과했다. JavaScript 예외는 0건이었다. 실제 카메라·모델·사람은 사용하지 않았다. 첫 전체 경로 시도에서는 26번 조건에서 시험 카메라 시작이 지연됐고, foreground 상태와 준비된 페이지 식별을 명확히 한 후 전체를 재검사했다. 실패 산출물은 보존하고 통과 결과와 구분했다.

실제 배정은 모든 64개 조합이 포함되도록 하되 한 사람에게 같은 원동작의 답을 반복해서 보여 주지 않는다. 참가자·원동작 계열·기기·손·순서와 연습을 통제하며, 표본·분모·수용 기준은 관측 전에 정한다. 첫 올바른 시도까지 시간·완료율·오선택·추적 소실·도움·중단·피로와 선호를 각각 기록한다. 모든 기능이 켜진 조건만 좋아 보여도 각 기능의 효과로 나눠 주장하지 않는다. 초기 무가림은 추가 정보이므로 사람/모델 비교에서도 동일하게 제공한다. 실제 동의·촬영·응답이 없으므로 효과 검증과 최종 화면 채택은 미완료다.
