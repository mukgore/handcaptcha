# 기존 prod B 화면에 선택 손을 연결한 실험 버전

기존 prod의 목표/카메라·진행/상태·결과 화면과 B 손바닥 안내를 기반으로 한다. `/experiments/prod_selected_hand/`를 열면 기존처럼 카메라 자동 시작 후 진행한다. 별도 준비 화면은 없다. 기존/A/B/C UI 비교에 선택 정책 효과가 섞이지 않도록 별도 실험 경로로 제공한다.

`python experiments/prod_selected_hand/build.py`는 prod B 복제본에 명시적 hook을 적용한다. 기준 hook이 바뀌면 빌드를 거부한다. 기존 prod/B 원본 파일을 수정하지 않는다. 추가 부분은 bridge.js와 기존 hand_selection/selection.js다.

두 손을 검출한 뒤 큰 유효 손을 8 callback 동안 안정화한다. 선택 손의 원본 좌표와 그 index의 handedness를 함께 기존 onRes에 전달한다. 검출 순서가 바뀌거나 먼 다른 손이 더 커져도 기존 선택을 위치·크기·형태로 추적한다. 사람의 신원 확인은 아니다.

소실/모호성·긴 callback 공백·시간 초과 시 시도 전체를 중단하고 카메라/재생/ghost를 정지한다. 좌우손 버퍼·목표·관문 hold·부분 구간을 초기화하고 늦게 완료된 문제 로드/결과 callback이 시도를 재개하지 못하게 한다. 다시 시작은 페이지 전체 reload로 선택/문제/timer/기록을 새로 만든다. 완료 뒤 카메라 loop도 재예약하지 않는다.

기존 38도/200ms 관문과 B0 채점 수학은 유지한다. 새 정책은 gate callback gap >=200ms이면 hold 초기화, 선택 후 callback gap >500ms이면 중단, 첫 선택부터 trial 60초 제한이다. 값은 명시적 공학 초기값이며 실제 기기/사람에 검증된 기준이 아니다. 낮은 fps·빠른 움직임에 따른 중단과 사용자 부담을 확인해야 한다. 이 정책을 운영 기준으로 채택한 결과는 아니다.

선택/관문/phase/중단/완료 event는 메모리에 최대1000개 기록하며 버튼으로만 JSON 저장한다. 저장본은 정책과 상대 페이지 시각/이벤트이며 영상/좌표/참가자 ID를 새로 복사하지 않는다. 기존 prod의 원래 결과/점수/설정된 전송 계약은 유지된다. 손 면 자동 판정 성공이나 사람/공격 성능으로 기록하지 않는다.

Node 연결/실제 생성 HTML async 검사: `node --test experiments/prod_selected_hand/bridge.test.cjs experiments/prod_selected_hand/async.test.cjs`. 9개를 통과했다. 실제 카메라/모델을 실행한 사람 실험은 별도다. 생성본의 score 수학이 기준과 같은지도 빌드 변경 때 함께 확인한다.

2026-11-04 사용자 PC 실기 확인: 사용자가 카메라/목표 영상 표시, 선택 손 유지, 선택 손 소실 후 중단의 세 항목이 정상이라고 보고했고, 전체 다시 시작 후 새 카메라/문제로 정상 진행됨도 후속 확인했다. 네 항목을 사용자 PC 기능 확인으로 기록한다. 브라우저/카메라 모델·반복 수·원시 사건 로그는 수집하지 않았다. 한 번의 사용자 확인이며 여러 기기·새 사람 비교나 보안 검증이 아니다.
