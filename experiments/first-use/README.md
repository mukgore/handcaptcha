# 손동작 CAPTCHA 첫 사용 평가

## 실행

저장소 루트에서 `node experiments/first-use/serve.cjs`를 실행한다. 다른 기기에서 평가하려면 영상 시킹에 필요한 범위 요청을 지원하는 HTTPS 호스트에서 두 페이지를 제공한다.

| 조건 | 로컬 주소 |
| --- | --- |
| A · 기존 화면 | [hand_captcha_prod.html](http://127.0.0.1:8765/hand_captcha_prod.html?study=first-use) |
| B · 개정 화면 | [첫 사용 화면](http://127.0.0.1:8765/experiments/first-use/?study=first-use) |

두 조건 모두 `custom01 → custom03` 순서로 시작 프레임에서 손바닥을 향한 기존 문제를 제시한다. 가림이 적용된 MP4, 원본 프레임 번호 기반 시킹, 좌표 반전, 자세 매칭 기준, 채점 함수와 결과 화면은 GitHub의 `hand_captcha_prod.html`을 따른다. 첫 자세는 정지 상태로 제시하고, 자세가 일치한 뒤 다음 키프레임까지 기존 구간을 재생한다. B에서는 문제를 가리는 동안 첫 프레임을 준비하고, 손바닥 방향과 왼손·오른손 판정이 약 0.45초 동안 안정적으로 유지되면 문제를 표시한다. 손등, 옆면 또는 방향을 판단하기 어려운 자세에서는 준비 화면이 계속 표시된다. B 수행 중 연결이 끊기면 해당 시도를 미완료로 기록하고, 재연결 후 같은 문제 순서의 새 시도를 준비한다.

## 진행

1. 사전 노출이 있는 사람으로 권한, 자동 시작, 두 영상의 잘림과 위치를 확인한다. 360 × 640 CSS px에서 준비 화면의 예시·미리보기와 수행 화면의 두 영상이 보이는지 확인한다. 스마트폰과 PC에서 왼손·오른손 각각의 손바닥, 손등, 옆면을 보여 주고 전환 여부를 기록한다.
2. 화면, 수행 방법, 다른 사람의 시도를 본 적 없는 참가자를 모집한다. 기기 종류별로 A 또는 B 한 조건에 무작위 배정하고 카메라 권한 초기 상태, 문제 순서, 안내와 관찰 상한을 맞춘다. 관찰 상한은 파일럿에서 정한다.
3. **“화면을 보고 진행해 주세요.”**라고 안내한다. 첫 시도 중에는 자세 힌트를 주지 않는다. 상한 도달, 참가자 중단, 또는 기술 실패 시 첫 시도를 종료한다. 도움을 주거나 다시 시도한 경우 이후 수행을 별도로 기록한다.
4. 종료 후 **“처음에 화면에서 무엇을 하라고 한다고 생각했나요?”**, **“손을 어디에 어떻게 보여줘야 한다고 생각했나요?”**라고 묻고 참가자의 표현을 그대로 기록한다.

## 관찰표

참가자 한 명당 아래 항목을 한 번 기록한다. 방향 판정은 평가 전에 예시를 보며 연구자끼리 맞추고, 평가 중에는 실시간으로 관찰한다. 원본 카메라 영상은 저장하지 않는다.

| 필드 | 기록 방법 |
| --- | --- |
| 참가자 코드, 조건, 기기, 권한 초기 상태, 사전 노출 | 사전 노출이 있으면 어떤 화면·설명·시도를 접했는지 기록 |
| 무도움 모방 시작 | 실제 문제를 보고 그 동작에 맞춰 움직이려 했는지 관찰 |
| 첫 손 전체 노출 시 방향, 첫 모방 직전 방향, 문제 표시 순간 방향(참고) | 각각 손바닥 / 손등 / 옆면·판단 어려움 / 손 없음 / 관찰 불가 |
| 스스로 수정 | 첫 노출이 손등이었고 도움 없이 첫 모방 전 손바닥으로 바꿨는지 기록 |
| 첫 시도 종료 | 완료 / 관찰 상한 / 권한 문제 / 기술 실패 / 자발적 중단 및 멈춘 단계와 이유 |
| 구간별 시간 | 첫 화면 → 카메라 요청 → 미리보기 표시 → 문제 표시 → 완료·중단. 기록할 수 없는 구간은 미측정 |
| 과제 이해와 손 제시 방법 | 종료 후 두 질문의 답변 |
| 인증 결과와 모방 점수 | 별도 필드에 기록. 미완료에는 점수란을 비워 둠 |

`?study=first-use`에서 브라우저 Performance 기록에 `handcaptcha:` 표식이 남는다. 페이지가 다시 로드되기 전에 표식을 확인하려면 기록을 시작한 상태로 평가하거나, 당시 콘솔에서 아래 명령을 실행한다. 시간은 해당 페이지의 시작 기준 밀리초다. B의 `palm_confirmed`는 자동 시작 조건을 만족한 시점, `problem_shown`은 첫 자세를 표시한 시점, `play_accepted`는 첫 움직임 구간의 영상 재생 요청이 수락된 시점이다. A는 카메라 요청 직전에 표식을 남기며 미리보기와 첫 문제는 영상 프레임을 표시한 때에 기록한다. 성과와 실제 모방 시작은 실시간 관찰을 사용한다.

```js
performance.getEntriesByType('mark')
  .filter(mark => mark.name.startsWith('handcaptcha:'))
  .map(({name, startTime, detail}) => ({name, ms: Math.round(startTime), detail}))
```

## 집계

- 무도움 모방 시작은 처음 화면을 본 사전 노출 없는 참가자 전체를 분모로 삼는다.
- 첫 자세 방향은 무도움으로 모방을 시작한 사람 중 방향을 판정할 수 있었던 사람의 분포를 제시한다. 손 없음, 관찰 불가, 판단 어려움은 인원을 따로 기록한다.
- 자가 수정 비율은 처음에 손등을 보였고 첫 모방 전 방향을 관찰할 수 있었던 사람을 분모로 삼는다.
- 각 수치를 조건별 인원수와 분모로 적고, 권한 문제, 기술 실패, 자발적 중단, 판단 어려움과 멈춘 이유를 함께 제시한다. 인증 통과율과 모방 점수는 별도로 보고한다.
